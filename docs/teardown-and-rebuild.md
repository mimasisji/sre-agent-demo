# Teardown & Rebuild — Zero-Cost Between Demos

When you're not actively using the demo, tearing everything down brings the Azure bill to **zero**. Rebuilding takes ~10–15 minutes automated + ~5 minutes of manual OAuth clicking in the portal.

## When to tear down

- Demo is done and you don't have another one scheduled for the next few days
- You're not going to touch the environment for 48+ hours
- You want to reset to a known-good state after experimenting

## When to keep it running

- You have a demo in the next 24–48 hours
- Your MCAP subscription has plenty of headroom (mine has $2,500/mo allowance)
- The value of your time is greater than the ~$10/day cost

**Cost of always-on:** ~$0.44/hour = ~$10.56/day = **~$317/month** for the SRE Agent (F1 App Service + free tiers of LAW/AI cover the rest at ~$0-2/mo).

⚠️ Stopping the agent from the portal (**Settings > Basics > Stop**) does **NOT** stop always-on billing — only **Delete** does.

## Tear down

```powershell
cd C:\Projects\sre-agent-demo
.\scripts\teardown.ps1
```

Will prompt you to type `DELETE` (uppercase) to confirm. Add `-Force` to skip the prompt for automation.

The deletion runs in the background; the CLI returns immediately. Full teardown takes 5–15 minutes but you don't have to wait.

## Rebuild

```powershell
cd C:\Projects\sre-agent-demo
.\scripts\rebuild.ps1
```

**Automated (~10 min):**
1. Create resource group
2. Deploy Bicep (App Service + App Insights + Log Analytics + alerts + action group)
3. `dotnet publish` + zip deploy + set `DEPLOYMENT_VERSION` + smoke test
4. Create User-Assigned Managed Identity for the agent
5. Grant Reader + Monitoring Reader on the RG
6. Create the Azure SRE Agent (SystemAssigned + UserAssigned identity)
7. PATCH the agent's `logConfiguration` and `knowledgeGraphConfiguration`

**Manual — portal only (~5 min):**
1. Open the agent in Azure Portal (URL is printed by the script)
2. **Logs** → add both connectors (LAW then App Insights) using the wizard
3. **Code** → click `+` → select GitHub → OAuth to `mimasis_microsoft/sre-agent-demo`
4. **Knowledge files** → click `+` → drag-drop 8 files:
   - `docs/architecture.md`
   - `docs/slo-runbook.md`
   - `docs/known-issues.md`
   - `docs/historical-incidents/incident-001.md` through `incident-005.md`

## After the rebuild

Verify the app is healthy:
```powershell
Invoke-RestMethod https://sredemo-mim-app.azurewebsites.net/health
```

Reset any leftover feature flags:
```powershell
.\scripts\toggle-failure.ps1 -FailureMode $false
.\scripts\toggle-failure.ps1 -DbTimeout $false
```

Optionally reseed telemetry so the agent has historical patterns to reference:
```powershell
.\scripts\seed-telemetry.ps1 -Cycles 1 -Quick   # ~14 min
```

## What survives teardown

Nothing in Azure. But **your repo is intact** — the app source, Bicep, scripts, docs, and demo backup screenshots all live in `main`. That's what makes the rebuild fast.

## What's lost on teardown

- All historical telemetry in App Insights / Log Analytics
- Any chat history you had with the agent
- The `ADMIN_TOKEN` (a new GUID is generated by Bicep on every deploy)

**None of that affects the demo** — the seed script regenerates telemetry, and the demo prompts don't depend on prior agent chats.
